# Umut Oku — professional portfolio

## Platform
web

## Stack
User requires .NET and its UI, with eventual GitHub hosting. Implementation choice: ASP.NET Core 10, a progressively enhanced HTML/CSS/JavaScript interface, and a static export for GitHub Pages. The .NET API supports a deterministic architecture demonstration; Pages uses the same published demonstration data. No deployment is claimed by local completion.

## Users
Corporate recruiters, engineering managers and senior backend interviewers evaluating Umut Oku for another enterprise role. The user confirmed recruitment and technical reputation as the priority on 2026-10-29.

## Product Purpose
Make relevant backend experience understandable quickly, then let a technical reader examine engineering decisions, experience and learning. Primary actions: view selected work, read the CV, contact via LinkedIn or public professional email. The user explicitly rejected a repository showcase: repositories are research evidence, never the visitor's required reading.

## Positioning
Architecture-minded .NET and distributed systems engineering across product/catalog, Elasticsearch, PostgreSQL, Redis, events, identity, integrations, payments and operations. The user explicitly corrected an overly payment-centred presentation: breadth, technology stack, dashboards, real measurements, experience and concrete accomplishments must be visible. Payments are one strong domain among several. Complementary AI/agent/retrieval work belongs with clearly labelled personal projects and training. Do not invent an Architect job title or universal expertise.

## Evidence on Hand
Existing portfolio, LinkedIn, GitHub, two user-provided CV PDFs, authorized Jira developer-filtered records and scoped source inspection. LinkedIn supplies employment history. Jira supplies task scope and current status. No independently measured uptime, throughput, revenue, performance gains or verified certification totals have been supplied; do not invent them. The newer CV and LinkedIn have conflicting historical end months: use years in the site and record the discrepancy for review.

## Capabilities and Constraints
English and Turkish, responsive layout, keyboard navigation, reduced motion, meaningful content without JavaScript, a capability and learning map, a real downloadable CV, and accessible architecture exploration with synthetic sample scenarios. Work examples omit company and provider names; the factual employment timeline retains employer names. Never expose internal source code, Jira keys, customer data, private endpoints, credentials or operational records in the public bundle. Diagrams are explanatory demonstrations, not production topology.

## Brand Commitments
Umut Oku. The user approved a dark, interactive systems-workshop direction and then clarified enterprise recruitment. Professional and precise voice. The experience should make expertise memorable without undermining credibility.

## Product Principles
Evidence before superlatives. Clear personal contribution. Direct access to work and contact. Innovation through useful interaction. Honest project maturity.

## Open Decisions
The user requested free GitHub hosting. Target: Umutoku/umutoku.github.io. Publish only the reviewed, sanitised portfolio source. The dashboard summarises twelve engineering tracks and 47 verified LinkedIn learning records. Live measurements come only from the current browser visit. Never connect the public dashboard to employer environments; never label curated or simulated values live. A separate .NET hosting provider is unnecessary for the free static site.
