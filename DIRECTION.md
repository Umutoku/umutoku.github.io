# Portfolio direction

## THESIS
Make Umut Oku's backend engineering judgment tangible to enterprise recruiters and engineering managers. Show concrete work first, then let a technical visitor explore a deliberately uncertain distributed-system outcome.

## OWN-WORLD
A systems workshop: graphite surfaces, amber selection, readable Host Grotesk, thin rules and an interactive landscape spanning product, search, data, cache, messaging, identity, payments and operations. The interface is its own illustration. Verified learning records and local browser measurements supply the dashboard; metrics are never invented.

## STORY
Identify the engineer and broad system scope, inspect anonymous work examples, try cache/search/event/payment scenarios, inspect the learning dashboard, read employment history, explore twelve capability areas and learning records, then contact or download the CV. Closed work rows state actual contributions. Payments are one domain, not the organising theme. Repository names, cards and lists are excluded at the user's explicit request.

## FIRST VIEWPORT
A direct role and .NET introduction beside a large two-line statement. Eight selectable domain nodes show the engineering landscape. Each explains relationships and decision boundaries; this is a capability map, not a production topology or a sequential flow. The first lab scenario explores a Redis cache miss. On mobile the map becomes two columns and retains full labels.
